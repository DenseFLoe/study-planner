# 双端本地排课联合优化（2026-10-23）

本轮已修改正式 Swift / Java 排课器：现有单节移动与两节交换之后，再加入一批课节的联合重排。应用不依赖 Python 或 OR-Tools，原评分定义、默认三倍例外及原有进度/历史处理均保留。安装包包含该改进；尚未执行安装或真实设备交互验收。

## 改法与范围

每次释放连续 1–4 天中的 3–12 节课、最多 4 个科目，按照各科原有队列交织、重新选择日期。区域外任务在本次尝试中保持开始时间，并在两端保留休息间隔。窗口、课程日期、整节时长和顺序均在构造时检查；只有所有取出的课节都放回、整份评分按已保存顺序严格改善才采用。中途超预算的未完成分支不采用。

剪枝采用乐观容量、各科最晚开课时间和偏好分数下界。下界允许同一份剩余学习量同时出现在多个未来日期，刻意放宽，只用于排除不可能改善的分支；最后的选择仍调用原完整课表评分。没有把多个目标加权求和。

沿用规模保护：最多 600 个已排块、6 门课、366 天。小例至多 40000 次下界评估、2000 个完整候选，每个邻域最多 12000 次评估；超过 24 块或 7 天的大例收紧到 6000 次评估、300 个完整候选，每个邻域最多 1500 次评估。还按 `课节数 + 天数×科目数` 缩减预算。Java 保留线程取消检查。这是有界改进搜索，不给出全局最优或无解证明。

## 实际结果

使用与提交 `88444e9` 完全相同的 32 个合成输入，对照该提交中已保存的旧算法结果：5 例严格改善、27 例相同，0 例评分退步，所有课程已排入分钟逐科相同。27 个可行小例均达到先前 CP-SAT 已证明的全部评分最优值；这只是这些具体输入的外部验证，不代表新算法一般能证明最优。4 个原来排不全的无解例仍未排全，本轮没有增加可行解找到率的证据。

新的完整运行经过 83 次 Swift 原评分复核和独立窗口、顺序、休息、浮动占用校验。历史实验定义与完整旧向量见 [首次对照](reference-results.md)。旧耗时取首次实验记录，新耗时为本轮 Release 优化的单次原生运行，未在相同瞬间测量；小差异有系统负载噪声，不作跨设备性能保证。

实际验证：Swift StudyCore 全部 299 项通过；Android 全套脚本通过，其中偏好模块 692 个检查，包含原有 24 种规则排列、2 组密集跨端案例及新增 49 组联合修复跨端案例。新增49组涵盖两个联合搬移案例的24种优先级顺序及默认三倍例外，Swift与Java逐任务相同。已有测试还覆盖部分完成、实际开课下界、历史保留、浮动事项、保存的拖动顺序、课程日期、长短课节、普通块、不可完成大负载与预算耗尽语义。

## 本地验收

用本轮生成的 Mac app / Android APK，在备份日程后打开，沿用已保存规则，点“保存并重排”查看新课表。重点核对各科待补总量、截止日、课节先后和15分钟休息，再看多科分布及每日负担。此操作留给用户安排，本轮不启动应用或操作真实手机。
