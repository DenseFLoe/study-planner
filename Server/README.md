# 学习日程私人云同步

这是待部署的 Linux 服务端包；构建包不会连接你的服务器。两端应用默认关闭云同步，热点功能继续可用。App 可用「HTTPS 直连」或「SSH 密钥」两种方式连接同一台服务器，两种配置分别保存。包内不含个人日程、服务器地址、真实访问码、SSH 私钥或 TLS 私钥。

## 工作方式

Mac 与 Android 每次保存实际变化后，把全部可同步记录（课程、固定事项、任务、完成记录、学习设置及删除标记）打成 gzip JSON 文件。离线文件在应用私有目录排队，服务器确认且本地提交合并结果后才清除。本地数据库还可重建未传的最新完整包。导入、热点同步产生的新变化也会进入云同步；无变化保存不新建包。

服务器按记录的 `modifiedAt`（实际修改 Unix 毫秒）比较新旧，相同时间以逻辑版本、设备 ID 决定。独有记录合并，相同记录去重，删除标记持续留在最新快照内。文件的 `createdAt` 和上传时间不决定记录输赢。设备应启用自动校时；同一记录的并发字段修改仍按整条记录选胜者，不做逐字段编辑合并。缺少记录不视作删除，必须传明确删除标记。

服务器先把上传包写入受限临时文件，再用每批最多 256 条或约 512 KiB 文本的外部排序、双路归并处理记录；历史账本和删除任务不会整体加载进 Java 堆。只有当前业务数据、相关删除标记进入排程工作集，继续复用 Android 的确认恢复、去重及排程校验逻辑。必要时重新排未来未确认任务，保留完成历史。每次有实际变化才生成新版本，完整 gzip 快照与服务器身份写入成功后才对外可见。最新与旧版合计最多十份；重启继续同一身份与版本。不会把每个原始上传包无限保存。收到损坏包、重复上传或断线重试不会覆盖为空数据。两端下载后合入当前本地记录，保住传输期间的本地修改；云进度与热点游标独立。

应用打开、回到前台、运行时网络恢复、修改后尝试同步。Mac 打开期间每小时检查，退出/休眠后不能保证执行；Android 使用系统 JobScheduler 每小时有网检查，可能因省电或强制停止而延迟。失败保留待传文件，可手动重试。不会因打开云设置而自动启用。

## 构建

仓库根目录执行 `./Scripts/build-server.sh`，得到 `dist/学习日程-云同步服务端.tar.gz`。编译需要 JDK 11+；部署只需 Java 11+ 运行环境。JSON-java 20240303 的来源、校验值与许可见 `JSON-java-LICENSE.txt`。依赖缺失时脚本从 Maven Central 下载并校验固定 SHA-256。

## 后续服务器安装

目标为使用 systemd 的 Linux。先在服务器安装 Java 11+ 与 openssl，解压部署包，再在解压目录显式运行 `sudo ./install.sh`。脚本创建专用无登录用户，安装程序与服务文件。首次在服务器本地生成访问码文件，升级保留访问码、配置和数据；安装不会自动启动。升级会暂停旧服务，检查后手动重新启动。这一节是系统级安装，适合独占服务器；合租服务器或没有 sudo 权限时改用下一节的普通用户安装，两种方式选其一。

- 程序：`/opt/study-planner-sync`
- 配置：`/etc/study-planner-sync/server.env`
- 服务访问码：`/etc/study-planner-sync/token`，仅在服务器本地安全读取并填写 App；不要复制到聊天、Git、脚本参数或日志。
- 数据：`/var/lib/study-planner-sync`，`server-id` 与最近十个 `.json.gz` 文件；与程序分离。

服务默认只监听 `127.0.0.1:8787` 的 HTTP。公网接入前必须配置 HTTPS 反向代理，禁止直接开放该内部端口。没有域名也可使用公网 IP 的受信任 IP 证书并自动续期，具体证书工具与端口需部署时检查服务器后确定。反代允许至少 32 MiB 请求与足够长的上传时间，关闭请求正文及 Authorization 日志。App 只接受 HTTPS 根地址，不接受跳转，也不跳过证书校验。

检查配置与反代后执行 `sudo systemctl enable --now study-planner-sync`。两端的“学习设置 → 云端同步”填写同一个 HTTPS 地址（可为公网 IP）和服务访问码，再启用并保存。Mac 留空访问码可沿用钥匙串保存的值；Android 访问码以 Keystore AES-GCM 加密后保存。访问码与 SSH 管理密钥无关。本版一个服务实例对应一个私人同步空间，两端共用访问码；轮换服务器访问码后两端都要更新，不提供多用户或逐设备撤销。改用下文的 SSH 密钥方式时，App 固定访问 `127.0.0.1:18090`（普通用户安装的默认监听）；系统级安装默认监听 `127.0.0.1:8787`，仍需按下文 HTTPS 方式接入。

服务器身份改变或版本倒退时，App 保留本地数据并停止应用该结果；核对服务器后重新保存配置才重新绑定。不要随意删除 `server-id`，也不要通过换旧版本文件名伪装新版本。

## 合租服务器：普通用户安装

服务端包也提供普通用户安装，供合租或共享服务器使用：不需要 root，不创建系统用户，也不写 `/opt`、`/etc` 或 `/var/lib`。在解压后的服务端包目录中显式运行：

```bash
./install-user.sh /绝对路径/到/java
```

参数是 Java 可执行文件的绝对路径。服务器需已有 Linux Java 11+；也可以自行解压一份 JRE，把其中 `java` 的绝对路径传给脚本。不需要 `sudo`。

安装后各路径都位于当前用户主目录：

- 程序、`config/server.env`、`config/token` 与 `data/` 均在 `~/projects/study-planner-sync/`。访问码只保存在 `config/token`，仅在服务器本地安全读取并填写 App；不要复制到聊天、Git、脚本参数或日志。
- 用户级服务文件为 `~/.config/systemd/user/study-planner-sync.service`，默认只监听 `127.0.0.1:18090` 的 HTTP。

安装不会自动启动。检查 `config/server.env` 与 HTTPS 反向代理后，显式执行 `systemctl --user enable --now study-planner-sync`。之后用 `systemctl --user status study-planner-sync` 查看、`systemctl --user restart study-planner-sync` 重启、`systemctl --user stop study-planner-sync` 停止；若服务器主人已为该账号开启 linger，退出 SSH 后服务继续运行。

普通用户与系统级安装都使用 `-Xms16m -Xmx96m`，systemd 设置 `MemoryHigh=160M`、`MemoryMax=192M`、`MemorySwapMax=0`、`TasksMax=32` 和 `CPUQuota=50%`（最多半个 CPU 核）。同时最多处理一个上传，忙时返回 HTTP 503 并提示 30 秒后重试。300 秒内最多启动三次，失败重启间隔 30 秒，避免崩溃循环持续争抢共享服务器资源。

`127.0.0.1:18090` 仅是本地 HTTP 监听，不要直接公开。公网访问需要 HTTPS 反向代理，端口和安全组需要服务器主人协调；两端 App 仍只接受可信 HTTPS 根地址，不接受跳转，也不跳过证书校验。也可以不配置反向代理，改用下一节的 SSH 密钥方式：App 通过 SSH 连接服务器并把 `127.0.0.1:18090` 转发到本机，无需公网开放该端口，也不需要域名或 TLS 证书。

备份：`~/projects/study-planner-sync/backup-user.sh ~/projects/study-planner-backups`。备份只包含 `data`，不包含 `token`，仍需安全复制到服务器之外。

升级：重跑新版服务端包内的 `install-user.sh`。升级保留访问码、配置、`server-id` 与快照，但会停服；完成后检查状态，再手动启动。

## App 连接方式：HTTPS 直连与 SSH 密钥

两端 App 的「云端同步」设置提供「HTTPS 直连」与「SSH 密钥」两张可选卡片。两种方式访问同一个服务实例和同一份数据，但地址、密钥与访问码分别保存，切换卡片不会覆盖另一套配置；同一时间只按已保存的连接方式同步。

**HTTPS 直连**：填写服务器公网可访问的 HTTPS 根地址和服务访问码。App 只接受可信证书的 HTTPS 根地址（可为受信任的公网 IP 证书），不接受跳转，也不跳过证书校验。按上文配置反向代理后即可使用，不要求 App 所在网络提供其他通道。

**SSH 密钥**：App 在本机建立 SSH 连接，只把服务器本机的 HTTP 监听转发到本机使用。需要填写：

- 服务器地址：SSH 主机名或 IP，示例 `<服务器地址>`。
- SSH 端口：默认 `22`，按服务器实际监听填写。
- 登录用户名：示例 `<登录用户名>`。
- 导入私钥：选择本机的 OpenSSH / PEM 私钥文件；私钥设了口令时填写私钥口令。
- SHA256 服务器指纹：首次连接时由 App 读取，需与服务器主人核对后再保存。服务器主人可在服务器上执行 `ssh-keygen -lf <服务器主机公钥路径>` 查看指纹。
- 服务访问码：SSH 方式仍需服务访问码，它按 `Authorization: Bearer <SERVICE_ACCESS_CODE>` 使用，与 SSH 私钥、服务器指纹不是一回事。

SSH 连接内固定访问 `127.0.0.1:18090`，对应上文“合租服务器：普通用户安装”的默认监听，因此不需要把 18090 开放到公网，也不需要域名或 TLS 证书，更不需要 Tailscale 等额外组网。系统级安装默认监听 `127.0.0.1:8787`，仍按 HTTPS 反向代理方式接入；SSH 卡片不提供任意转发目标。

安全边界：

- 首次保存的指纹之后若发生变化，App 停止连接并提示重新核对，不会自动接受新指纹。
- 私钥与私钥口令只保存在本机安全存储，不写入日程数据库、同步包、备份或安装包，也不会随云同步上传。
- SSH 连接只在同步时建立，同步结束或失败后立即关闭，不保持常驻隧道。
- Mac 使用系统 OpenSSH，Android 使用内置 SSH 库；服务器只需允许该账号登录并转发到本机 `127.0.0.1:18090`。
- 两种方式都仍需自行保管服务访问码，不要把访问码、私钥或私钥口令写进文档、聊天或脚本参数。

## 接口与版本找回

所有接口都要求 `Authorization: Bearer <SERVICE_ACCESS_CODE>`，占位符不能直接使用。

| 接口 | 用途 |
|---|---|
| GET `/cloud/status` | 服务器身份、版本、保留数量 |
| POST `/cloud/snapshot` | 完整 gzip JSON 账本，返回合并后的版本号 |
| GET `/cloud/latest` | 最新完整 gzip 快照 |
| GET `/cloud/history` | 最近十版清单 |
| GET `/cloud/history/<revision>` | 下载仍保留的指定旧版，用于核对与找回 |

文件格式 1：`format / archiveID / device / createdAt / records`，服务端输出另有 `serverID / revision`。每条记录沿用热点字段 `kind / id / payload / deleted / version / device / sequence / modifiedAt`，payload 为 Base64 JSON，业务日期仍采用自 2001-01-01 UTC 起秒数；modifiedAt、createdAt 为 Unix 毫秒。普通业务备份不是云数据包，不能直接向接口上传。压缩包上限 32 MiB，解压上限 128 MiB，合并后的记录总数最多 20 万条，单条 payload 延用现有上限。服务端排程工作集最多 1 万条且记录 JSON 文本合计不超过 6 Mi 字符，超限返回 HTTP 413，不替换现有快照；两端保留待传数据。历史中与当前排程无关的删除任务只走磁盘合并，不占用这个工作集额度。临时磁盘用量随包大小增长，建议数据所在分区至少预留 1 GiB 空间；操作结束清理，异常退出残留在下次启动时清理。

旧版提供下载核对，当前没有一键恢复界面。仅恢复旧服务器文件会被两端识别为版本回退。找回时先下载隔离核对，再把需要的内容作为新的用户修改保存；不要直接覆盖正在同步的数据库。

## 备份与恢复

十版历史用于近期找回，不能代替服务器外备份。可在服务器执行 `sudo /opt/study-planner-sync/backup.sh /绝对路径/备份目录`，脚本暂停服务后打包数据并恢复原运行状态，不包含访问码。把备份安全复制到服务器之外。

灾难恢复：先停服，完整备份现有数据，在同一数据目录恢复整份备份（包含 server-id），保持专用用户权限，再启动。恢复版本可能比设备记忆的版本旧；先核对数据，确认后在两端重新保存云配置，触发本地完整数据与服务端重新合并。SSH、TLS 和访问码凭证另按服务器密钥管理方式恢复。

## 验证边界

可在本地执行 `Server/test.sh` 与 `Scripts/test-cloud.sh`，使用临时目录和合成课表，验证合并、并发上传、操作时间、删除、失败重试、损坏包、持久化、最近十版及跨语言互读，不接触正式日程。新增 `Scripts/test-ssh.sh` 验证连接配置、旧 HTTPS 配置兼容及指纹拒绝。显式提供 `STUDY_SSH_TEST_HOST / USER / KEY_PATH / FINGERPRINT`（各变量均有 `STUDY_SSH_TEST_` 前缀，可选 `PORT`）可启用真实 SSH 探测：Android 共用核心在 JVM 上、Mac OpenSSH 已通过真实服务器无访问码状态请求、Ed25519 登录、指纹拒绝及隧道关闭检查，没有读写真实日程。Android 真机的 Keystore、界面、后台重试、两端私钥口令与耗电仍待设备验收；不宣称真实日程同步已经通过。

服务端内存：`Scripts/test-cloud-memory.sh` 使用合成的 12 万条旧删除任务与 16 万条新删除任务，在独立 **64 MiB Java 堆**下验证启动、上传、重复上传、损坏包、持久化与重启。`Server/test.sh` 另外覆盖外部排序跨批重复键、离线确认恢复、撤销确认、历史删除标记保留、工作集超限、并发忙重试和原有十版保留/磁盘失败行为。`Scripts/test-cloud.sh` 检查现有 Swift/Java 格式互读与客户端流程。测试不读取正式日程，合成压力测试通过不等于 Android 真机或 macOS 界面验收完成。
