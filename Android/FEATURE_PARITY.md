# Mac / Android 功能对照 · 1.6.3

本轮将 Mac 已有的业务功能接入 Android。界面采用手机操作方式：长按拖放和“交换本日顺序”均可交换；搜索通过按钮打开；文件导入、导出使用 Android 系统文件选择器。Mac 的菜单快捷键、窗口布局和 Finder 打开方式由手机对应入口替代。

- 全局顶部“正在同步中”与旋转动画覆盖云同步、实际局域网交换及接收后的本地刷新；等待 Mac 连接的接收窗口不视为正在传输。完成、失败与超时后结束显示。
- 固定课表新增“粘贴文字，识别日程”：本机后台保守提取日期、时间与重复规则，最多30000字、20条候选。相对日期按识别当天北京时间解释；每条候选须“核对并添加”，沿用原编辑与冲突处理，不直接保存识别结果。
- 修复：提前全量确认、顺序交换或同步后刷新预警时，以实际保存的待进行课表核算未排入量、风险和每日学习量，不用未应用的新草稿替换诊断。
- 修复：课程编辑中删除手动课节时，统一清除其安排和完成流水，扣除属于已删除课节的基础进度，保留其余课节与进度，保存删除标记；预览使用相同规则，失败不保存部分改动。
- Android 课程页新增极限压缩只读预览，**仅显示 Mac 计算并经成功云同步收到的结果**。没有算法实现或算法参数，不修改正式任务、进度、截止日期或可学习时段。展示课程完成时间和按日期选择的方案时间线；最多同步前2000条预览项目（必要时按字节上限缩减），超出明确提示在 Mac 查看。业务输入变化、跨天或来源签名不一致时标记“待更新”，旧方案仍可查看；缺少结果时引导先在 Mac 计算并云同步。Android 本地缓存只有成功云同步能写入，局域网同步、备份恢复与本地排程不发布展示结果。
- **学习监督明确只支持 Mac**：Android 不加入应用绑定、播放检测、后台监督、监督通知或自定义提示音。未来“全部迁移 / 对齐 Mac”不得改变此边界，除非用户明确重新授权。仓库约束见 AGENTS.md。立即学习和应用内主页字号设置也不在本轮迁移范围。

验证：运行 Android/test.sh 与 Mac 的 CompressedSchedulePreviewTests、CompressedScheduleControllerTests、SavedScheduleAssessmentTests、CourseEditingStoreTests 及云同步相关测试；合成跨语言样例覆盖 Swift gzip → Java 合并、旧设置兼容、结果上限、输入变化及跨天失效。自动检查不代表手机触摸、动画、真机云同步或 Mac 实际通知已验收。

本包手机验收：覆盖安装后确认1.6.3；检查浮动卡片交换前后的时间；在固定课表粘贴“明天下午3点到5点开会”，核对后添加，另试冲突与取消编辑；切页观察云同步提示在成功/失败后结束；先在新版 Mac 完成压缩计算、云同步，再在手机云同步并查看方案，修改手机进度后应显示“待更新”。不需要配置学习监督。

## 云同步连接方式（1.6.1 构建 16）

设置 → 云端同步提供「HTTPS 直连」「SSH 密钥」两张可选卡片，选择后点击保存才切换使用方式；地址、私钥与服务访问码分别保存，互不覆盖。

- HTTPS 直连：只接受可信证书的 HTTPS 根地址，不接受跳转，也不跳过证书校验。现有 HTTPS 部署与 systemd 文档继续有效，见 Server/README.md。
- SSH 密钥：填写服务器地址、SSH 端口（默认 22）、登录用户名、导入私钥（可填私钥口令）、SHA256 服务器指纹和服务访问码；连接后在服务器内部固定访问 `127.0.0.1:18090`。无需 Tailscale，不要求公网开放 18090 或有域名。
- 指纹：首次读取的服务器指纹需与服务器主人核对后保存；之后指纹变化必须停止连接、重新核对，不能自动接受新指纹。
- 访问码：SSH 仍需要服务访问码（按 `Authorization: Bearer <SERVICE_ACCESS_CODE>` 使用），它不是 SSH 私钥。
- 本机边界：私钥与私钥口令只保存在本机安全存储，不进入日程同步包、备份或安装包。
- 连接生命周期：只在同步时建立 SSH 连接，同步结束或失败后关闭；Mac 使用系统 OpenSSH，Android 使用内置 SSH 库。

验收边界：共享合并、跨语言 gzip 互读回归继续有效。Android 共用 SSH 核心在 JVM 上、Mac OpenSSH 在真实服务器上通过了 Ed25519 登录、指纹不匹配拒绝、内部 HTTP 无访问码状态探测及隧道关闭检查，没有读写真实日程。Android 真机的 Keystore、卡片界面、私钥口令与后台断线恢复仍待设备验收。

## 自动验证与边界

- `./Android/test.sh`：Java 排课、确认、设置、交换、合并、网站及网盘导入测试；Node 合成分页测试及共享脚本一致性检查。
- `./Scripts/test.sh --filter 'AndroidParityTests|DailyTaskOrderingTests|CourseMergingTests|WebCourseSnapshotTests|StudyLoadTests|LessonOrderingTests|GenericCourseDigestTests|NetdiskDigestTests|NetdiskDedupTests'`：104 个 Mac 测试通过，包含 Android 合成数据解码与交换顺序恢复。
- `Android/tests/fixtures/desktop-parity.json` 由 Android 测试生成，只有合成课程和合成分享，没有个人日程或登录凭据。
- 学丞课程包与直播课节使用 Mac 的 `generic:` / `:live:` 标识；同名但不同目录位置的直播保留独立进度。跨页面继续识别会保留之前的章节，重复抓取不会增加同一课节。回放时长只有在标题与目录一致时才采用。SQLite 或同步后恢复风险提示时，只更新派生诊断，不替换共享课表。
- 当前环境没有可运行的 Android 模拟器 / adb；本轮尚未进行新 APK 的真机触摸、WebView 登录与直播回放验收。原有文档中的 Android 15 设备同步验收属于此前版本，不能当作本轮新增界面的验收结果。
- 通用识别依赖设备 WebView 支持加载前脚本注入；旧 WebView 会明确提示升级，允许在页面内切换课程后再识别。网站没有返回时长的课节保留，但不计入可排学习量；已发布且必须有时长的视频缺数据会拒绝导入。
- 网页导入在独立进程和独立 WebView 数据目录中进行（API 28 及以上）；每次打开及关闭都清除登录 Cookie、网页存储与缓存。API 26 / 27 同样清除会话，该应用其他功能不使用 WebView。课程快照及网盘文件信息只保留白名单字段，分享凭据不会进入保存、同步或导入临时文件。

## 新包手机验收步骤

1. 用现有签名覆盖安装 `dist/学习日程-安卓版.apk`；设置页确认版本 1.6.3。已有记录应保留。不要通过卸载旧版来升级。
2. 选一天有至少两个未确认任务的日期，分别用拖放和“交换本日顺序”交换；重开、重排及与 Mac 同步后核对顺序和课间休息。
3. 搜索课时并跳转，核对周统计；合并两门测试课程，预览、排序、确认与撤销后核对剩余量。
4. 在导入窗口自行登录网站，核对课节、时长、进度并预览；重复抓取后应更新同一课程并保留本地完成流水。
5. 读取自己的夸克分享，分别检查提取码、子目录、多个分页、未知时长、目录批选及合并；关闭窗口重新进入应需要重新登录。
